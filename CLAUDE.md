# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Команды

```bash
npm run dev        # vite dev server, порт 5173
npm run build      # tsc -b && vite build -> dist/
npm run lint       # oxlint
npm run preview    # раздать собранный dist (проверка прод-сборки)
```

Тестов в репозитории нет.

## Что это

Чистилка спрайтов: заделка дырок в обводке, сглаживание контура, чистка
цветовой ряби, пикселизация непиксельных ассетов. Всё считается **в браузере**,
серверной части нет — сборка деплоится как статика (Vercel определяет Vite сам).
Файлы пользователя никуда не загружаются, и это не деталь реализации, а
обещание в интерфейсе: не вводить сетевых вызовов с пользовательскими данными.

## Архитектура

Поток данных: `File` → `createImageBitmap` → `OffscreenCanvas` → `ImageData` →
пул воркеров → `Uint8ClampedArray` → холст превью и PNG-блоб для ZIP.

- `src/lib/pixelfix.ts` — всё ядро, чистые функции над типизированными
  массивами, без DOM. Единственная точка входа — `processImage(bitmap, settings)`.
- `src/worker.ts` — тонкая обёртка: принимает буфер, зовёт ядро, отдаёт результат.
- `src/pool.ts` — пул воркеров по числу ядер (максимум 4), очередь задач.
- `src/App.tsx` — состояние, инструменты, плавающие панели, ZIP.
- `src/EditorCanvas.tsx` — холст: зум, панорама, лассо, клики инструментов.
- `src/Toolbar.tsx` — вертикальный ряд инструментов и переключатели панелей.
- `src/FloatingPanel.tsx` — плавающее окно настроек, помнит своё место.
- `src/storage.ts` — сессия: localStorage для настроек, IndexedDB для файлов.

### Порядок шагов в `processImage`

Порядок не переставлять, каждый шаг опирается на результат предыдущего:
пикселизация → порог альфы → снятие обводки → внутренние полости → закрытие
щелей → правило соседей → despeckle → снятие светлой каймы → сглаживание
контура → слияние похожих цветов → палитра и сглаживание цветовых зон →
рисование обводки снаружи → перекраска кромки → defringe → бинаризация альфы
→ растяжка цвета за контур.

Отсюда основной сценарий («Обводка заново» в интерфейсе): снять старую
обводку целиком, восстановить тело заливкой от соседей, выровнять силуэт,
нарисовать обводку заново по чистому краю. Чинить рваную обводку на месте
бесполезно — её форма повторяет рваный силуэт.

Пикселизация идёт первой, потому что вся дальнейшая чистка должна работать уже
по новой сетке. Растяжка цвета — последней, потому что ей нужна финальная альфа.

### Приёмы, на которых держится качество

- **Заливка цвета — мода соседей, а не среднее.** `fillColors` расходится
  волной от известных пикселей и выбирает цвет голосованием, поэтому новых
  промежуточных оттенков не появляется. Замена на усреднение размоет пиксель-арт.
- **Палитра для голосования — не палитра для покраски.** Когда
  `paletteColors` равен нулю, `smoothRegions` голосует по авто-палитре из 32
  оттенков, но красит пиксель фактическим цветом ближайшего соседа из
  выигравшей зоны. Если красить цветом палитры, на богатом спрайте тридцати
  двух оттенков не хватает и цвета уезжают: фиолетовая кожа босса
  обесцвечивалась до серой (r−g падал с 40 до 20).
- **Голосование по палитре вместо работы с сырым цветом.** У картинки после
  масштабирования почти каждый пиксель уникален, голосовать не за что —
  поэтому `smoothRegions` и режим `pixelDominant` сначала строят палитру.
- **`regionKeep` защищает тонкие линии.** Пиксель меняет цвет, только если его
  оттенок слабее победителя в `(1 - keep)` раз. Без этого обводка в два пикселя
  проигрывает голосование заливке тела и растворяется.
- **Премультиплицированная альфа при уменьшении.** Иначе прозрачные пиксели
  подмешивают свой мусорный цвет в края.
- **`boxBlur` через интегральное изображение**, края продлеваются — иначе
  силуэт у рамки картинки подъедается.
- **Полости отбираются по толщине, а не по площади.** Артефакт — тонкая щель
  вдоль обводки: длинной она бывает, толстой нет. Настоящее отверстие
  переживает эрозию. На наборе из 30 ассетов это разделило 5946 артефактов
  (толщина 0–1, площадь до 197 px) и 14 настоящих отверстий (толщина ≥2,
  одно из них площадью всего 43 px). Отсюда `holeThickness`.
- **Снимается только тонкая лента у кромки.** `stripOutlineColor` ограничен
  глубиной `stripDepth` от края и морфологическим открытием: толстые области
  того же цвета (тёмные штаны, ботинки, волосы) переживают эрозию и остаются.
  Без открытия у персонажа сносило ноги целиком — тёмная одежда сливается с
  обводкой в одну связную область.
- **Новая обводка наращивается наружу** (`outlineGrow`), а не внутрь: иначе
  спрайт худел бы на толщину снятой каймы.
- **Обводка перерисовывается, а не чинится заливкой.** Заливка красит разрыв
  модой соседей, а вокруг разрыва соседей-заливки больше — обводка так и
  остаётся дырявой. Поэтому `outlineThickness` красит всю кромку найденным
  цветом обводки.
- **Порядок якорей в `mergeSimilar` и выборке тёмных в `detectOutlineColor`
  строго детерминирован** (частота, при равенстве — значение цвета), чтобы
  одинаковый вход всегда давал одинаковый результат.

### Ручные правки

`magicSelect` — «волшебная палочка»: заливка по связности и похожести цвета от
точки клика. Стирания живут в `App` как стопка мазков на ассет (индексы
пикселей), а не в `Settings`: они не должны попадать в ключ кэша результатов и
уходить в воркер как параметр. Применяются к декодированным пикселям перед
обработкой, поэтому переживают любую смену настроек.

Заливка идёт по связности, и обводка на спрайте связная: клик в неё уносит её
целиком по всему рисунку (на боссе это 83 тысячи пикселей). Поэтому есть
отмена последнего мазка и предупреждение, когда захвачено больше 15% силуэта.

Допуск держим низким (14): по замерам заливка почти не растёт до 24, а на 32
клик в обводку забирает уже 28% спрайта.

`removeBackground` — отдельный инструмент для картинок из интернета: заливка
внутрь от рамки по нескольким цветам сразу, взятым с самой рамки. Нескольким,
потому что «прозрачный» фон часто оказывается запечённой шахматкой из двух
оттенков: между её клетками расстояние 34.6, одним допуском её не взять, не
задев рисунок.

Обе заливки умеют добор края (`feather`): каждый следующий слой берётся с более
широким допуском. Без него на антиалиасной картинке остаётся светлая кайма —
1224 пикселя против одного с добором 2.

Замкнутые карманы фона (между рукой и телом, в петлях) заливкой от рамки не
достаются, поэтому `removeBackground` добирает их отдельно — но только когда
фон многоцветный и второй по частоте оттенок занимает в кармане не меньше
трети. Шахматка делит карман примерно поровну; у белка глаза или блика один
цвет доминирует, а прочие — единичные пиксели тени. Первая версия проверяла
только число оттенков и съедала глаза.

`fillPolygon` + инструмент «Вернуть лассо» — ручная страховка от таких
ошибок: обведённая область возвращается из оригинала. Правки поэтому хранятся
типизированной стопкой (`erase` / `restore`) и накатываются по порядку —
восстановление снимает пометку, поставленную более ранним стиранием.

`CompareViewer` перевписывает вид по `viewKey` (id ассета), а не по `before`:
стирание рисует новый объектный URL, и по нему зум сбрасывался бы после
каждого клика ластиком.

### Сессия

`src/storage.ts`. Настройки и состояние инструментов — в localStorage (пара
килобайт JSON, поднимаются синхронно в инициализаторе `useState`). Файлы и
правки — в IndexedDB: в localStorage они не влезут (лимит около пяти
мегабайт), а IndexedDB хранит Blob и `Int32Array` без сериализации. Потолки —
300 файлов и 150 МБ, выше сессия просто не сохраняется, о чём говорится в
статусе.

Восстановление нельзя защищать гардом по ref: в StrictMode он глушит второй
монтаж, и сессия не поднимается вовсе. Отмена — через флаг `alive`, повторный
запуск безвреден. Сохранение правок ждёт флага `restored`, иначе пустая карта
затрёт то, что лежало в базе.

### Раскладка редактора

Сверху строка файлов и действий, слева тулбар, центр — один холст. Настройки
живут не в боковой колонке, а в плавающих окнах: инструмент открывает своё.
Показ оригинала — кнопка «Оригинал» с удержанием, а не второй холст: сравнение
нужно моментами, а место на экране нужно всегда.

Состав открытых окон и их места сохраняются, поэтому раскладка переживает
перезагрузку вместе с сессией.

### Тонкости UI, которые легко сломать

- Пул воркеров создаётся лениво через `useState(() => new WorkerPool())`, а не
  в `useMemo` с cleanup: StrictMode монтирует дважды, и cleanup убивал бы
  воркеры насмерть.
- Результаты **не обнуляются** при смене настроек — предыдущий кадр держится на
  экране до готовности нового, иначе картинка мигает пустотой. Устаревший
  результат помечается сравнением `result.key` с сигнатурой настроек.
- `EditorCanvas` перевписывает вид только при смене `viewKey` или размера окна
  (`fitted` ref). Иначе зум сбрасывался бы после каждого движения ползунка и
  каждого клика ластиком.
- Колесо слушается через `addEventListener(..., { passive: false })`: React
  вешает пассивный обработчик, который не даёт отменить прокрутку страницы.
- Шахматка рисуется в экранных координатах, до трансформации холста, поэтому
  клетки не растут вместе с картинкой.
- Буферы уходят воркеру через transfer, поэтому в `pool.run` делается копия —
  исходник ещё нужен для превью «до».
