## Что это

Чистилка спрайтов: заделка дырок в обводке, сглаживание контура, чистка
цветовой ряби, пикселизация непиксельных ассетов. Всё считается **в браузере**,
серверной части нет — сборка деплоится как статика (Vercel определяет Vite сам).
Файлы пользователя никуда не загружаются, и это не деталь реализации, а
обещание в интерфейсе: не вводить сетевых вызовов с пользовательскими данными.

## Архитектура

Поток данных: `File` → `createImageBitmap` → `OffscreenCanvas` → `ImageData` →
пул воркеров → `Uint8ClampedArray` → холст превью и PNG-блоб для ZIP.

- `src/lib/pixelfix.ts` — всё ядро, чистые функции над типизированными
  массивами, без DOM. Единственная точка входа — `processImage(bitmap, settings)`.
- `src/worker.ts` — тонкая обёртка: принимает буфер, зовёт ядро, отдаёт результат.
- `src/pool.ts` — пул воркеров по числу ядер (максимум 4), очередь задач.
- `src/App.tsx` — состояние настроек, список ассетов, галерея, ZIP.
- `src/CompareViewer.tsx` — пара холстов с общим состоянием вида.

### Порядок шагов в `processImage`

Порядок не переставлять, каждый шаг опирается на результат предыдущего:
пикселизация → порог альфы → внутренние полости → закрытие щелей → правило
соседей → despeckle → снятие светлой каймы → сглаживание контура → слияние
похожих цветов → палитра и сглаживание цветовых зон → перерисовка обводки →
defringe → бинаризация альфы → растяжка цвета за контур.

Пикселизация идёт первой, потому что вся дальнейшая чистка должна работать уже
по новой сетке. Растяжка цвета — последней, потому что ей нужна финальная альфа.

### Приёмы, на которых держится качество

- **Заливка цвета — мода соседей, а не среднее.** `fillColors` расходится
  волной от известных пикселей и выбирает цвет голосованием, поэтому новых
  промежуточных оттенков не появляется. Замена на усреднение размоет пиксель-арт.
- **Голосование по палитре вместо работы с сырым цветом.** У картинки после
  масштабирования почти каждый пиксель уникален, голосовать не за что —
  поэтому `smoothRegions` и режим `pixelDominant` сначала строят палитру.
- **`regionKeep` защищает тонкие линии.** Пиксель меняет цвет, только если его
  оттенок слабее победителя в `(1 - keep)` раз. Без этого обводка в два пикселя
  проигрывает голосование заливке тела и растворяется.
- **Премультиплицированная альфа при уменьшении.** Иначе прозрачные пиксели
  подмешивают свой мусорный цвет в края.
- **`boxBlur` через интегральное изображение**, края продлеваются — иначе
  силуэт у рамки картинки подъедается.
- **Полости заливаются только мелкие.** Дырка от артефакта — считаные
  пиксели, крупная замкнутая область почти всегда часть рисунка (вырез под
  ручку). Отсюда `holeMaxArea`.
- **Обводка перерисовывается, а не чинится заливкой.** Заливка красит разрыв
  модой соседей, а вокруг разрыва соседей-заливки больше — обводка так и
  остаётся дырявой. Поэтому `outlineThickness` красит всю кромку найденным
  цветом обводки.
- **Порядок якорей в `mergeSimilar` и выборке тёмных в `detectOutlineColor`
  строго детерминирован** (частота, при равенстве — значение цвета), чтобы
  одинаковый вход всегда давал одинаковый результат.

### Тонкости UI, которые легко сломать

- Пул воркеров создаётся лениво через `useState(() => new WorkerPool())`, а не
  в `useMemo` с cleanup: StrictMode монтирует дважды, и cleanup убивал бы
  воркеры насмерть.
- Результаты **не обнуляются** при смене настроек — предыдущий кадр держится на
  экране до готовности нового, иначе картинка мигает пустотой. Устаревший
  результат помечается сравнением `result.key` с сигнатурой настроек.
- `CompareViewer` перевписывает вид только при смене ассета или размера окна
  (`fitted` ref). Иначе зум сбрасывался бы после каждого движения ползунка.
- Колесо слушается через `addEventListener(..., { passive: false })`: React
  вешает пассивный обработчик, который не даёт отменить прокрутку страницы.
- Шахматка рисуется в экранных координатах, до трансформации холста, поэтому
  клетки не растут вместе с картинкой.
- Буферы уходят воркеру через transfer, поэтому в `pool.run` делается копия —
  исходник ещё нужен для превью «до».
